## Offline evaluation runtime

Run from the repository root under Node 22 with locked JS dependencies (`npm ci`). The one-day Parquet reader uses Python 3 with `pyarrow`, `pandas`, and `numpy`; install into an isolated virtual environment and set `STOCK_PICKER_PYTHON` to its Python executable. This avoids relying on global Python or a platform-specific path. Run `node scripts/audit_eval_data.mjs` first; regenerate the manifest and clear derived research caches if raw data changes. Generated artifacts in `output/stock-picker-eval/` are research-only, not production snapshots.

The signal interface is `store.asOf(T)`: immutable observation rows, dates only through T, and fail-closed reads. Labels receive a separate clock. Local calendar entries are explicit closures only: a weekday with missing data and no verified closure is retained as an unavailable slot rather than compressed out of the execution horizon. Intraday files require a complete regular session per symbol; minute `pre_close` on the final bar is not the prior day's close. Positive volume without an observed turnover amount is **not** evidence of liquidity. Floats representing A-share quoted prices are normalized to ticks before limit-price comparisons. The raw snapshot lacks security names; the current name/classification map cannot prove a security was not ST on an earlier date.

OOS is reserved for a single full-window run after IS evidence and a frozen configuration hash. Never clear its attempt marker to optimize a result. Historical constituent versions are absent (`static_taxonomy_caveat: true`).
